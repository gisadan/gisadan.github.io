# 카페 재고 자동발주 서비스 — 사업계획서 (v0.1)

> 키오스크/POS 판매 데이터를 읽어, 점주가 발주를 *누르지 않아도* 원두·부자재가
> 떨어질 시점을 예측해 자동으로 채워주는 카페 특화 재고·발주 자동화 서비스.

작성일: 2026-06-27 · 상태: 아이디어 검증 단계 (브레인스토밍 정리본)

---

## 1. 문제 (Problem)

- 카페는 원두·우유·시럽·컵 등 소모품을 **수기/전화/카톡으로 발주**한다. 떨어지면 그때 주문.
- 키오스크·POS에 **판매 수량이 전부 디지털로 찍히는데**, 그 데이터가 재고·발주와 연결되어 있지 않다.
- 무인카페는 **매장에 사람이 없어** 재고를 눈으로 보고 발주할 주체가 없다 → 떨어지면 곧장 매출 0.

## 2. 타겟 (Who) — 무인·소형 카페

- 한국 커피시장 규모 **19~21조 원**, 커피전문점 **10만 개+**. 단, 폐업률 > 창업률의 포화 시장(영세·이탈 잦음).
- **무인카페가 성장 축** — 초기비용·인건비 낮아 폭증, 60대+ 점주까지 유입.
- 무인카페는 ① 키오스크가 100% 있어 판매 데이터가 디지털이고 ② 사람이 없어 자동화가
  *nice-to-have가 아니라 필수* → **우리 가치가 가장 강하게 통하는 쐐기(wedge)**.
- 프랜차이즈 가맹점(메가커피 등)은 **본사 차액가맹금(유통마진)** 구조 때문에 본사가 막음 → 1차 타겟에서 제외.
  (개인·무인 카페는 본사가 없어 최저가 발주 자유)

## 3. 경쟁 (Competition)

| 플레이어 | 정체 | 핵심 |
|---|---|---|
| **코케비즈**(컨슈머브릿지) | 카페 특화 납품 플랫폼 | 2년 만에 가입매장 **2만**(전국 카페 ~20%). 간편발주+월정산 자동화 |
| **마켓로스팅** | 커피 원·부자재 직거래 앱 | 9만 개인카페 대상 |
| **마켓보로**(식봄/마켓봄) | 범용 식자재 플랫폼+SaaS | 식봄 거래액 2,341억(2025), POS 자동 재고차감 보유. CJ프레시웨이 403억 투자 |
| **푸드팡** | 외식업 새벽배송(직접물류) | 농산물 중심, 누적투자 218억 |
| 커피바바·두고 | 카페용품 도매 | — |

**핵심 통찰:** 위 플레이어는 전부 **"점주가 직접 누르는 간편발주"**. 아무도
**"안 눌러도 알아서 채워주는 예측발주"**를 카페에서 제대로 안 했다 → **여기가 빈틈.**

## 4. 차별화 (Wedge)

> **"무인·소형 카페를 위한, 판매 데이터 연동 *예측* 자동발주"**
> 점주가 발주를 *하는* 게 아니라, 시스템이 판매량 보고 *알아서* 떨어질 시점을 예측 →
> 멀티벤더 최저가/빠른배송으로 발주 → (장기) 공급사가 미리 보충.

단계별 비전:
1. 판매 데이터 → 소진량 자동 계산 → **예측 자동발주** (핵심)
2. 여러 공급사 입점 → **최저가 / 재고 / 빠른배송** 라우팅
3. 공급사가 매장 재고를 알고 **미리 보충(VMI/예측배송)** — endgame, 자본 무거움 → 후순위

## 5. 핵심 난제 & 해법 — POS/키오스크 연동

데이터 난이도는 결국 **"닫힌 POS" 하나로 수렴**한다. 두 겹의 어려움:

1. **파편화·폐쇄:** 오케이포스(26만 가맹점)·포스뱅크(POS·키오스크 1위)·나이스·KIS 등 벤더마다
   자기 DB·자기 API. 표준 없음. 데이터 소유권 이슈로 잘 안 열어줌.
   (단 토스플레이스 등 **신형 POS는 Open API 제공** — 균열 진행 중)
2. **BOM 환산:** "라떼 100잔" → "원두 1kg + 우유 30L"로 바꾸려면 매장별 레시피 매핑 필요 +
   시음·폐기 노이즈. 그래서 기존 플레이어가 회피하고 "간편발주"로 우회한 지점.
   → **단, 판매 잔수(라떼 100잔) 자체를 얻는 건 쉬움.** 어려운 건 환산과 판단.

### 해법: "POS 연동은 전제조건이 아니라 보너스" — 데이터 입력 등급제

| 티어 | 데이터 유입 | 점주 노력 | 적용 대상 |
|---|---|---|---|
| **오픈 API** | 토스플레이스 등 자동 | 0 | 열린 POS 매장 (기본 탑재) |
| **로컬 에이전트** | POS PC(윈도우)에 프로그램 설치 → 로컬 DB 읽기/자동 export 전송 | 0 (설치 1회) | **닫힌 POS 점유율 1~2위만** 외과수술식 |
| **엑셀 업로드** | 점주가 상품별 판매 export 파일을 주 1회 업로드 | 주 1회 클릭 | 나머지 닫힌 POS (폴백) |
| **IoT 실측** | 원두 호퍼 스마트저울·우유냉장고 센서로 직접 측정 | 0 | 무인카페 (POS 자체를 건너뜀) |

- **재고는 실시간이 필요 없다.** 원두는 주 1~2회 발주하는 느린 신호 → 주 단위 데이터로 충분.
- **로컬 에이전트 주의:** 파편화(벤더·버전별 리버스), POS 업데이트 시 파손, 약관 회색지대,
  설치·보안 거부감 → **만능 아님. 1~2위 벤더에만.** 규모 커지면 정식 제휴로 졸업.
- **데이터 거버넌스 — 신뢰/법적 안전의 핵심:**
  데이터 주인은 **업주**다. "업주가 동의해, 자기 매장 이득 위해, 자기 데이터를 쓰는 것" →
  무단 탈취가 아니라 정당한 사용. 벤더 반발 약화.
  - 설계 A(SaaS): 매출이 클라우드로. 더 똑똑한 예측·매장간 벤치마킹.
  - 설계 B(엣지) ⭐: POS PC에서 계산 끝내고 **"원두 5kg 발주" 결론만** 전송. 원본은 매장 밖으로 안 나감.
    → 프라이버시·벤더반발 최소. *"우리는 매출 안 가져갑니다"*가 마케팅 메시지가 됨.

## 6. 수익모델 (가설)

- 공급사 거래 **중개수수료**(마켓보로형, 가벼움) — 초기 메인 가설.
- SaaS 구독(예측발주·재고관리 툴) — 보조.
- (장기) 예측배송/물류 마진(푸드팡형, 무거움) — 자본 확보 후.

## 7. 진입 전략 / 로드맵 (초안)

1. **Phase 0 — 가치 증명:** 엑셀 업로드 + 오픈 API(토스) 1종으로 MVP. 무인·소형 카페 소수에
   "예측발주(원두/우유/컵)" 정확도 검증. BOM은 메뉴 1회 등록으로 최소화.
2. **Phase 1 — 자동화 확대:** 닫힌 POS 1~2위 로컬 에이전트. 공급사 2~3곳 입점(원두 카테고리 락인).
3. **Phase 2 — 마켓플레이스:** 멀티벤더 최저가/재고/배송 라우팅.
4. **Phase 3 — 예측보충:** 공급사 VMI/예측배송(콜드체인·MOQ 해결 후).

## 8. 리스크

- 코케비즈가 자본·매장 수 선점 → **속도 경쟁**. "예측 자동발주"라는 차별점을 빠르게 못박아야.
- 예측이 핵심 가치인데 **콜드스타트**(초기 소진 데이터 부족 시 정확도 약함).
- 영세·이탈 잦은 고객군 → 객단가·리텐션 관리 필요.
- 닫힌 POS 로컬 에이전트의 유지보수·법적 리스크.
