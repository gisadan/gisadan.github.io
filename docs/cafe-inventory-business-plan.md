# 카페·외식업 구매 운영체제 (Procurement OS) — 사업계획서 / Seed 덱 초안 (v0.4)

> ## **"점주가 발주를 하는 게 아니라, 시스템이 발주한다."**
> ## **판매 데이터를 실제 구매로 바꾼다.**
>
> *Shopify가 온라인 쇼핑몰의 운영체제였다면, 우리는 오프라인 카페·외식업의 **구매 운영체제(Procurement OS)**가 된다.*
> *(규모를 동일시한다는 뜻이 아니라, 'OS'가 하는 역할 — 한 영역의 흐름 전체를 표준 인프라로 장악 — 을 가리키는 비유.)*
>
> 키오스크/POS 판매 데이터를 읽어, 점주가 *누르지 않아도* 부자재가 떨어질 시점을 예측해 자동으로 채우는
> 서비스로 시작한다. 최종적으로 만드는 것은 *재고관리 앱*도 *발주앱*도 아니다 —
> **POS → 수요예측 → 발주 → 공급사 → 배송**으로 도는 카페·외식업 **구매 흐름 전체의 인프라**다.
> *(장기 비전: Procurement에 머물지 않고 POS→Inventory→Procurement→Supplier→Finance를 잇는 **Supply Chain OS**로 확장 가능. 단 지금은 Procurement에 집중하는 게 현실적 포지셔닝.)*

작성일: 2026-06-27 · 상태: 아이디어 검증 단계 (다음 단계 = 현장 검증)

## 1. 문제 (Problem) — Pain = 돈

카페는 원두·우유·시럽·컵을 **수기/전화/카톡으로** 발주한다. POS엔 판매량이 디지털로 찍히는데 재고·발주와 끊겨 있다.
그 결과 **돈이 새는** 세 방향 *(아래는 보수적 예시값, 실제는 §14 인터뷰로 검증)*:

| 새는 곳 | 메커니즘 | 보수적 추정 |
|---|---|---|
| **품절 (재고 부족)** | 인기 원두·우유 떨어지면 그 시간 못 팖 | 월 **~15만원** 매출 손실 |
| **과잉·폐기** | 불안해서 과발주 → 유통기한 폐기, 현금 묶임 | 월 **~10만원** |
| **수동 발주 노동** | 재고 세고 단가 비교하고 주문 | 월 **10시간+** (≈8만원 기회비용) |

→ 투자자 언어로: "편함"이 아니라 **회수 가능한 돈**. (§10 Unit Economics에서 ROI로 정량화)

## 2. 왜 지금인가 (Why Now)

*"왜 5년 전엔 안 됐고 지금은 되는가?"* — 네 흐름이 **이제야** 동시에 맞물렸다.

| 변화 | 5년 전 | 지금 |
|---|---|---|
| **POS API 개방** | 전부 폐쇄 | 토스플레이스 등 **Open API 등장** |
| **키오스크 보급** | 일부만 | 무인·소형 카페까지 **사실상 표준** → 데이터 100% 디지털 |
| **무인카페 증가** | 미미 | **성장 축**으로 폭증 → 자동화 *필수* 수요 |
| **수요예측 성숙** | 룰 기반, 부정확 | 모델 성숙 → **적은 데이터로도** 소진 예측 실용화 |

## 3. 솔루션 & 핵심 루프 — 본질은 AI가 아니라 Closed Loop

이 사업의 본질은 *AI*가 아니라 **닫힌 순환(Closed Loop)**이다. 이 사이클이 계속 도는 것이 'OS'의 본질:

```
        ┌────────────────────────────────────────┐
        │                                        │
     [판매] ──▶ [예측] ──▶ [발주] ──▶ [배송] ──▶ [판매] ──▶ [예측] ...
     POS·키오스크   소진계산   자동주문   공급사     다시 데이터로
        │                                        │
        └──────── 돌수록 예측 정확↑·해자↑ ─────────┘
```

루프가 한 바퀴 돌 때마다 데이터가 쌓여 다음 예측이 정확해진다 → 점주는 더 의지 → 거래액↑.
경쟁사가 '예측 버튼'을 흉내 내도, **루프를 끝까지 닫지 못하면**(발주·공급사·배송까지) 같은 게 아니다.

## 4. 타겟 (Who) — 개인·소형 카페 전반 (무인은 초기 비치헤드)

- 한국 커피시장 **19~21조 원**, 커피전문점 **10만 개+**. 영세·이탈 잦지만 모수 거대.
- **최종 타겟: 개인·소형 카페 전반** — 본사 없어 최저가 발주 자유, 수기 발주가 대부분.
- **초기 진입은 무인카페** — 키오스크 100%(데이터 디지털) + 사람 없음(자동화 필수). 레퍼런스 쌓고 **일반 카페로 확장**.
- (장기) 소형 체인·로컬 프랜차이즈. 대형 프랜차이즈(메가커피급)는 **본사 차액가맹금**으로 외부 발주 차단 → 후순위/제휴.

## 5. 경쟁 & 포지션 — 경쟁축은 '예측'이 아니라 '구매 흐름 전체'

| 플레이어 | 정체 | 핵심 |
|---|---|---|
| **코케비즈** | 카페 특화 납품 플랫폼 | 2년 만에 **2만 매장**(전국 ~20%). 간편발주+월정산 |
| **마켓로스팅** | 원·부자재 직거래 앱 | 9만 개인카페 대상 |
| **마켓보로**(식봄/마켓봄) | 범용 식자재 플랫폼+SaaS | 식봄 거래액 2,341억, CJ프레시웨이 403억 투자 |
| **푸드팡** | 외식업 새벽배송(직접물류) | 농산물 중심 |

**'예측발주'만으론 부족하다** — 경쟁사가 버튼 하나 붙이면 따라온다. 진짜 차이는 *기능*이 아니라 **포지션**:

```
   기존: "발주 플랫폼"            우리: "구매 운영체제(OS)"
   = 더 편하게 사는 쇼핑몰        = POS→예측→발주→공급사→배송→정산 전 흐름을 깔고 표준이 됨
   점주가 결정 → 산다             시스템이 결정 → 점주를 의사결정에서 제거
```

> **핵심 한 줄:** 우리가 파는 건 발주 편의가 아니라 **"점주를 구매 의사결정에서 제거하는 것"**이다.
> 경쟁은 예측 정확도 싸움이 아니라 **구매 흐름을 누가 먼저 인프라로 장악하느냐**의 싸움이다.

## 6. 핵심 난제 — POS 연동 / SKU 표준화 / BOM

1. **닫힌 POS:** 오케이포스(26만)·포스뱅크(1위)·나이스·KIS 등 벤더별 자기 DB·API, 표준 없음.
   → **해법: 데이터 입력 등급제**(아래).
2. **SKU 표준화 (실은 BOM보다 더 어렵고, 더 큰 자산):**
   `서울우유 1L` = `서울우유 흰우유 1L` = `서울우유 1000ml` = `서울우유 1L(10개입)` — 이게 **같은 상품인지** 판단해야 멀티벤더 최저가 비교가 성립한다. 마켓플레이스가 되는 순간 **상품 마스터 데이터(SKU 표준)**가 생기고, 이건 경쟁사가 쉽게 못 따라오는 자산이다.
   > **우리는 카페 공급망의 SKU 표준을 만든다.**
3. **BOM 환산:** "라떼 100잔→원두 1kg" 매장별 레시피 매핑 → 메뉴 1회 등록으로 최소화. 판매 잔수 자체를 얻는 건 쉬움.

### 해법: "POS 연동은 전제조건이 아니라 보너스" — 데이터 입력 등급제

| 티어 | 데이터 유입 | 점주 노력 | 대상 |
|---|---|---|---|
| **오픈 API** | 토스플레이스 등 자동 | 0 | 열린 POS (기본) |
| **로컬 에이전트** | POS PC에 설치 → 로컬 DB 읽기 | 0 (설치 1회) | **닫힌 POS 1~2위만** |
| **엑셀 업로드** | 판매 export 주 1회 업로드 | 주 1회 클릭 | 나머지 닫힌 POS |
| **IoT 실측** | 스마트저울·냉장고 센서 | 0 | 무인카페 (POS 우회) |

- 재고는 실시간 불필요(주 단위로 충분). 로컬 에이전트는 1~2위 벤더에만(유지보수·약관 리스크).
- 데이터 거버넌스: 주인은 **업주**. 엣지 설계 시 "원두 5kg 발주" 결론만 전송 → *"매출 안 가져갑니다"*.

## 7. 공급사 확보 전략 — *이 사업의 진짜 난관*

> 투자자 1순위 질문: **"공급사는 왜 당신 플랫폼에 입점하나?"** 점주 모객보다 이게 더 무겁다.
> 입점은 한 줄이 아니라 **계약 → ERP 연동 → 상품 등록 → 가격 관리 → 배송 관리**의 무거운 과정이다.

**전략 1 — 카테고리 한 줄 락인 (닭-달걀 깨기):** 전 품목을 한 번에 모으지 않는다.
**한 카테고리(원두)부터** 소수 공급사로 시작해 거래를 일으키고, 그 거래량을 미끼로 다음 카테고리를 끌어온다.

```
   원두 5곳 ─▶ 컵·소모품 3곳 ─▶ 우유 2곳 ─▶ 시럽·소스 2곳
                    = 약 12개 공급사로 카페 품목 ~90% 커버
```

**전략 2 — 공급사 ERP를 미끼로:** 입점의 무게(상품등록·가격·배송관리)를 **우리가 SaaS로 대신 풀어줌**(Stage 4 수익원과 동일). "주문도 받고, 관리 툴도 공짜로" → 입점 동기.
**전략 3 — 수요를 들고 협상:** 점주 N곳의 *예측된 미래 수요*를 데이터로 보여주며 "이 물량을 너에게 몰아주겠다" → 공급사는 안정적 주문을 위해 가격을 낮춘다(역경매).

## 8. 네트워크 효과 & Moat Timeline

플라이휠: **점주↑ → 구매데이터↑ → 예측정확도↑ → 공급사 입점↑ → 가격경쟁/빠른배송 → 점주↑ → 거래액↑ → 수수료↑** (반복).

**해자는 언제 생기나 (Moat Timeline):**

| 매장 수 | 해자의 원천 | 단계 |
|---|---|---|
| **0 ~ 100곳** | **기능**(예측발주가 실제로 됨) | 제품 검증 |
| **100 ~ 1,000곳** | **데이터**(예측 정확도·SKU 표준 누적) | 데이터 우위 |
| **1,000 ~ 10,000곳** | **마켓플레이스**(공급사 밀도·가격) | 네트워크 효과 |
| **10,000곳+** | **금융**(매입 데이터 기반 SCF) | 인프라 락인 |

> 데이터 네트워크 효과: 매장 100곳보다 **1,000곳일 때 예측이 더 정확**하고, 거래액이 크면 공급사가 더 들어오고,
> 공급사가 많으면 점주는 더 싸고 빠르게 받는다. 시간이 갈수록 **누적 데이터·공급망 밀도**가 쌓여
> 신규 경쟁자가 따라오기 구조적으로 어려운 진입장벽이 된다. (코케비즈는 *쇼핑 데이터*, 우리는 *예측 데이터*를 쌓는다 — 종류가 다르다.)

## 9. 수익모델 — 단계적 확장

| 단계 | 수익원 | 전제 |
|---|---|---|
| **Stage 1** | **SaaS 구독** (예측발주·재고관리 툴) | 매장 확보 |
| **Stage 2** | **주문 중개수수료** (거래액 %) | 마켓플레이스 형성 |
| **Stage 3** | **광고/입점** (공급사 노출·우선순위) | 공급사 경쟁 |
| **Stage 4** | **공급사 ERP** (주문·재고·정산 SaaS) | 공급사 락인 |
| **Stage 5** | **Working Capital / Supply Chain Finance** (매입 데이터 기반 운전자본·외상정산) | 거래 데이터 축적 |

> Stage 5는 *내세우는 핵심이 아니라 결과*다. 우리는 각 매장이 *언제·뭘·얼마치 사는지*를 가장 정확히 아는 주체가
> 되고, 그 데이터는 곧 **공급망 신용 데이터**다. 영세 카페일수록 운전자본(SCF) 수요가 커, 데이터가 쌓인 뒤 자연히 따라오는 레이어다.

## 10. Unit Economics (1페이지) — *보수적 가정, 파일럿 검증 전제*

> 근거: 카페 원가율 25~33%, 개인카페 월매출 400만(주거)~1,000만+(일반), 원두 1kg 2~2.5만, 객단가 4,550원.

### (A) 매장 1곳 — 우리가 버는 돈
| 항목 | 가정 | 값 |
|---|---|---|
| 매장 월매출 | 개인카페 현실값 | 1,000만원 |
| 원부자재 구매액 | 원가율 30% | 월 300만원 |
| └ 플랫폼 통과액(GMV/매장) | 신선·베이커리 제외 ~70% | 월 **210만원** |
| 수수료 매출 | 7% | 월 14.7만원 |
| SaaS 매출 | 구독 | 월 3.9만원 |
| **합계 ARPU** | | 월 **약 18.6만원/매장** |

### (B) 매장 1곳 — 점주 ROI (왜 결제하나) · *보수적으로 하향*
| 점주 효익 | 월 가치 |
|---|---|
| 품절 방지(매출 보전) | +15만원 |
| 폐기/과잉재고 감소 | +10만원 |
| 발주·재고 노동 절감 | +8만원 |
| 최저가 비교 절감 (210만×3%) | +6만원 |
| **효익 합계** | **≈ 39만원/월** |
| 비용(구독료) | −3.9만원/월 |
| **ROI** | **≈ 10배** |

→ *"월 3.9만원 내고 ~39만원 번다."* (실제 인터뷰에서 더 크게 나오면 그때 상향)

### (C) 매장 1,000곳 (시장 1%)
| 지표 | 값 |
|---|---|
| 월 GMV (210만×1,000) | **21억원** |
| 연 GMV | **약 252억원** |
| 수수료 매출(7%) | 연 **≈ 17.6억** |
| SaaS 매출 | 연 **≈ 4.7억** |
| **합계 매출** | 연 **≈ 22.3억** |

> 코케비즈가 2만 곳(20%)을 모았다는 건 *모객이 된다*는 증명. 시장 10%(1만 곳)면 단순 비례로 **연 ~220억 + GMV 2,500억** + Stage 3~5.

## 11. Go-To-Market — 첫 100개 매장을 어떻게 확보하나

> 투자자는 제품보다 **유통(Distribution)**을 본다. 첫 100곳을 *직접 영업*이 아니라 **채널로** 확보한다:

| 채널 | 왜 강한가 |
|---|---|
| **무인카페 협회·커뮤니티** | 비치헤드 고객이 한곳에 모여 있음 |
| **키오스크 업체 제휴(B2B2B)** | 그들 고객이 곧 우리 타겟, 데이터까지 동시 확보 |
| **원두 공급사** | 자기 거래처 카페에 "발주 편해진다" 추천(공급사도 주문↑) |
| **세무사·창업 컨설턴트** | 카페 창업/운영 길목을 쥔 추천자 |

→ Phase 0의 핵심 가설: **"채널 1~2개로 첫 100곳을 CAC 낮게 확보 가능한가"**를 먼저 증명.

## 12. 왜 우리인가 (Why You) — *작성 필요*

- [ ] **도메인:** 카페/외식 운영·창업 또는 식자재 유통 경험?
- [ ] **기술:** POS 연동·데이터·예측·IoT 개발 역량?
- [ ] **네트워크:** 공급사·POS 벤더·파일럿 매장 접근성?
- [ ] **집착의 이유:** 직접 겪은 페인 스토리 (가장 설득력 큼)

## 13. 로드맵

1. **Phase 0 — 가치 증명:** 엑셀+토스 API MVP, 무인카페 소수에 예측 검증, 채널 1개로 100곳 시도. (SaaS)
2. **Phase 1 — 확장:** 일반 카페로, 닫힌 POS 1~2위 에이전트, 공급사 원두 5곳 락인.
3. **Phase 2 — 마켓플레이스:** 멀티벤더 라우팅 + SKU 표준. (수수료+광고)
4. **Phase 3 — 예측보충+SCF:** VMI/예측배송, 공급망금융. (금융)

## 14. 고객 검증 계획 — *지금 가장 중요한 일*

문서를 더 늘리기보다 **현장 데이터**를 붙인다. 이 세 결과가 기업가치를 가장 크게 끌어올린다:

1. **카페 점주 20명 인터뷰** — 현재 발주 방식 / 자동발주 위임 의향 / **월 지불의사(WTP)**
2. **공급사 10곳 인터뷰** — 입점 의향 / 중개수수료 감당 여부 / 가장 부담되는 연동
3. **MVP 파일럿 3~5곳** — 실제 **예측 정확도 / 품절 감소율 / 발주시간 절감 / 구매 전환율**

## 15. 리스크

- **공급사 온보딩**(가장 무거움) — 카테고리 락인·ERP 미끼·수요 협상으로 완화.
- 코케비즈 선점 → 속도 경쟁(구매 OS 포지션 선점).
- 예측 콜드스타트 / 영세·이탈 고객 리텐션.
- 닫힌 POS 에이전트 유지보수·법적 리스크.
- SCF는 연체·여신 규제 동반 → 데이터 축적 후.
