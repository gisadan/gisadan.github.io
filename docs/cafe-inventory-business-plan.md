# 카페 AI 구매 운영체제 (AI Procurement OS) — 사업계획서 (v0.2)

> ## **"점주가 발주를 하는 게 아니라, 시스템이 발주한다."**
>
> 키오스크/POS 판매 데이터를 읽어, 점주가 *누르지 않아도* 원두·부자재가 떨어질 시점을
> 예측해 자동으로 채우는 서비스로 시작한다. 그러나 우리가 최종적으로 만드는 것은
> *재고관리 앱*도 *발주앱*도 아니다 — **POS → AI 예측 → 발주 → 공급사 → 배송**으로 이어지는
> 카페·외식업 **구매 흐름 전체를 장악하는 인프라(AI Procurement OS)**다.

작성일: 2026-06-27 · 상태: 아이디어 검증 단계 (브레인스토밍 정리본)

---

## 1. 문제 (Problem)

- 카페는 원두·우유·시럽·컵 등 소모품을 **수기/전화/카톡으로 발주**한다. 떨어지면 그때 주문.
- 키오스크·POS에 **판매 수량이 전부 디지털로 찍히는데**, 그 데이터가 재고·발주와 연결되어 있지 않다.
- 무인카페는 **매장에 사람이 없어** 재고를 눈으로 보고 발주할 주체가 없다 → 떨어지면 곧장 매출 0.

## 2. 왜 지금인가 (Why Now)

투자자가 항상 묻는 질문: *"왜 5년 전엔 안 됐고, 지금은 되는가?"* — 네 가지 흐름이 **이제야** 동시에 맞물렸다.

| 변화 | 5년 전 | 지금 |
|---|---|---|
| **POS API 개방** | 전부 폐쇄. 데이터 못 뺌 | 토스플레이스 등 **Open API 등장** — 균열 시작 |
| **키오스크 보급** | 일부 매장만 | 무인·소형 카페까지 **사실상 표준** → 판매 데이터 100% 디지털 |
| **무인카페 증가** | 미미 | **성장 축**으로 폭증(저비용·무인) → 자동화 *필수* 수요 |
| **AI 예측 정확도** | 룰 기반, 부정확 | 수요예측 모델 성숙 → **적은 데이터로도** 소진 예측 실용화 |

→ "데이터를 뺄 수 있고(API) + 데이터가 디지털이고(키오스크) + 자동화가 절박하고(무인) + 예측이 정확해진" **딱 그 교차점**이 지금이다.

## 3. 타겟 (Who) — 개인·소형 카페 전반 (무인은 초기 비치헤드)

- 한국 커피시장 규모 **19~21조 원**, 커피전문점 **10만 개+**. 영세·이탈 잦은 포화 시장이지만 모수 자체가 거대.
- **최종 타겟: 개인·소형 카페 전반** — 본사가 없어 최저가 발주가 자유롭고, 발주를 수기로 하는
  곳이 대부분. 유인/무인 가리지 않고 "재고 떨어져 매출 끊김 / 발주가 귀찮음"은 공통 문제.
- **초기 진입(비치헤드)은 무인카페** — 시장 전체가 아니라 *처음 뚫고 들어갈 지점*으로만 활용:
  ① 키오스크가 100% 있어 데이터가 디지털, ② 사람이 없어 자동화가 *필수* → 가치가 가장 뾰족하게 통함.
  여기서 검증·레퍼런스를 쌓고 **일반 개인·소형 카페로 확장**한다.
- (장기) 소형 체인·로컬 프랜차이즈까지. 단 메가커피급 대형 프랜차이즈는 **본사 차액가맹금(유통마진)**
  구조 때문에 본사가 외부 발주를 막음 → 후순위/제휴 대상.

## 4. 경쟁 (Competition)

| 플레이어 | 정체 | 핵심 |
|---|---|---|
| **코케비즈**(컨슈머브릿지) | 카페 특화 납품 플랫폼 | 2년 만에 가입매장 **2만**(전국 카페 ~20%). 간편발주+월정산 자동화 |
| **마켓로스팅** | 커피 원·부자재 직거래 앱 | 9만 개인카페 대상 |
| **마켓보로**(식봄/마켓봄) | 범용 식자재 플랫폼+SaaS | 식봄 거래액 2,341억(2025), POS 자동 재고차감 보유. CJ프레시웨이 403억 투자 |
| **푸드팡** | 외식업 새벽배송(직접물류) | 농산물 중심, 누적투자 218억 |
| 커피바바·두고 | 카페용품 도매 | — |

**핵심 통찰:** 위 플레이어는 전부 **"점주가 직접 누르는 간편발주"**. 아무도
**"안 눌러도 알아서 채워주는 예측발주"**를 카페에서 제대로 안 했다 → **여기가 빈틈.**

```
            간편발주 (기존)              vs          예측발주 (우리)
   점주가 떨어진 걸 인지 → 앱에서 검색 → 주문      시스템이 소진 예측 → 자동으로 장바구니/발주
   = 더 편한 쇼핑                                = 점주를 의사결정에서 제거
```

## 5. 차별화 (Wedge) → AI 구매 운영체제로 확장

> **"개인·소형 카페를 위한, 판매 데이터 연동 *예측* 자동발주"** (무인카페부터 시작)
> 점주가 발주를 *하는* 게 아니라, 시스템이 판매량 보고 *알아서* 떨어질 시점을 예측 →
> 멀티벤더 최저가/빠른배송으로 발주 → (장기) 공급사가 미리 보충.

**자동발주는 입구일 뿐, 도착지는 구매 흐름 전체의 장악이다:**

```
POS/키오스크 ─▶ AI 예측 ─▶ 자동 발주 ─▶ 공급사 마켓플레이스 ─▶ 배송/정산/금융
   (데이터)     (두뇌)      (실행)        (네트워크)          (수익화)
```

단계별 비전:
1. 판매 데이터 → 소진량 자동 계산 → **예측 자동발주** (핵심 진입)
2. 여러 공급사 입점 → **최저가 / 재고 / 빠른배송** 라우팅 (마켓플레이스 전환)
3. 공급사가 매장 재고를 알고 **미리 보충(VMI/예측배송)** — endgame, 자본 무거움 → 후순위

## 6. 핵심 난제 & 해법 — POS/키오스크 연동

데이터 난이도는 결국 **"닫힌 POS" 하나로 수렴**한다. 두 겹의 어려움:

1. **파편화·폐쇄:** 오케이포스(26만 가맹점)·포스뱅크(POS·키오스크 1위)·나이스·KIS 등 벤더마다
   자기 DB·자기 API. 표준 없음. 데이터 소유권 이슈로 잘 안 열어줌.
   (단 토스플레이스 등 **신형 POS는 Open API 제공** — 균열 진행 중)
2. **BOM 환산:** "라떼 100잔" → "원두 1kg + 우유 30L"로 바꾸려면 매장별 레시피 매핑 필요 +
   시음·폐기 노이즈. 그래서 기존 플레이어가 회피하고 "간편발주"로 우회한 지점.
   → **단, 판매 잔수(라떼 100잔) 자체를 얻는 건 쉬움.** 어려운 건 환산과 판단.

### 해법: "POS 연동은 전제조건이 아니라 보너스" — 데이터 입력 등급제

| 티어 | 데이터 유입 | 점주 노력 | 적용 대상 |
|---|---|---|---|
| **오픈 API** | 토스플레이스 등 자동 | 0 | 열린 POS 매장 (기본 탑재) |
| **로컬 에이전트** | POS PC(윈도우)에 프로그램 설치 → 로컬 DB 읽기/자동 export 전송 | 0 (설치 1회) | **닫힌 POS 점유율 1~2위만** 외과수술식 |
| **엑셀 업로드** | 점주가 상품별 판매 export 파일을 주 1회 업로드 | 주 1회 클릭 | 나머지 닫힌 POS (폴백) |
| **IoT 실측** | 원두 호퍼 스마트저울·우유냉장고 센서로 직접 측정 | 0 | 무인카페 (POS 자체를 건너뜀) |

- **재고는 실시간이 필요 없다.** 원두는 주 1~2회 발주하는 느린 신호 → 주 단위 데이터로 충분.
- **로컬 에이전트 주의:** 파편화(벤더·버전별 리버스), POS 업데이트 시 파손, 약관 회색지대,
  설치·보안 거부감 → **만능 아님. 1~2위 벤더에만.** 규모 커지면 정식 제휴로 졸업.
- **데이터 거버넌스 — 신뢰/법적 안전의 핵심:**
  데이터 주인은 **업주**다. "업주가 동의해, 자기 매장 이득 위해, 자기 데이터를 쓰는 것" →
  무단 탈취가 아니라 정당한 사용. 벤더 반발 약화.
  - 설계 A(SaaS): 매출이 클라우드로. 더 똑똑한 예측·매장간 벤치마킹.
  - 설계 B(엣지) ⭐: POS PC에서 계산 끝내고 **"원두 5kg 발주" 결론만** 전송. 원본은 매장 밖으로 안 나감.
    → 프라이버시·벤더반발 최소. *"우리는 매출 안 가져갑니다"*가 마케팅 메시지가 됨.

## 7. 네트워크 효과 & 진입장벽 (왜 SaaS가 아니라 플랫폼인가)

이 사업의 본질은 *툴*이 아니라 **자가증식하는 마켓플레이스**다. 큰 돈은 수수료·거래액에서 나오고,
그 거래액은 아래 **선순환(플라이휠)**이 돌수록 기하급수로 커진다.

```
        점주 증가
           │
           ▼
      구매 데이터 증가  ──▶  예측 정확도 ↑ (매장 1,000곳 > 100곳)
           │
           ▼
      공급사 입점 증가  ◀── "주문 받으려면 들어와야 함"
           │
           ▼
      가격 경쟁 / 빠른 배송  ──▶  점주 혜택 ↑
           │
           ▼
       점주 더 증가  ──▶  거래액 ↑  ──▶  수수료 ↑
           └──────────── (다시 위로) ────────────┘
```

### 데이터 네트워크 효과 = 따라올 수 없는 해자

> 매장이 100곳일 때보다 **1,000곳일 때 예측 정확도가 더 높아진다**(소진 패턴·계절성·메뉴별
> 수요 데이터가 누적되므로). 정확도가 높아질수록 점주는 더 의지하고, 거래액이 커지면
> **공급사는 더 많은 주문을 받기 위해 입점**하며, 공급사가 많아질수록 점주는 **더 낮은 가격과
> 빠른 배송**을 받는다. 이 선순환은 시간이 지날수록 누적 데이터·공급망 밀도가 쌓여
> **신규 경쟁자가 따라오기 구조적으로 어려운 진입장벽**이 된다.

즉, 코케비즈가 매장 수에서 앞서 있어도 — 그들은 *간편발주(쇼핑 데이터)*만 쌓고 우리는
*소진·예측 데이터*를 쌓는다. 데이터의 종류가 다르고, 우리 데이터가 예측을 강화하는 쪽이라
**시간이 갈수록 격차가 벌어지는 자산**이다.

## 8. 수익모델 — 단계적 확장 (SaaS → 마켓플레이스 → 금융)

단일 수수료가 아니라, 데이터·거래량이 쌓일수록 **수익원이 한 층씩 열리는** 구조.

| 단계 | 수익원 | 설명 | 전제 |
|---|---|---|---|
| **Stage 1** | **SaaS 구독** | 예측발주·재고관리 툴 월 구독 | 매장 확보 |
| **Stage 2** | **주문 중개수수료** | 공급사 거래액의 % (마켓보로형) | 마켓플레이스 형성 |
| **Stage 3** | **광고/입점** | 공급사 노출·프로모션·우선순위 광고 | 공급사 경쟁 발생 |
| **Stage 4** | **공급사 ERP** | 공급사 측 주문·재고·정산 SaaS | 공급사 다수 락인 |
| **Stage 5** | **금융 (BNPL)** ⭐ | 원두 오늘 주문 → **30일 후 결제**. 매입 데이터 기반 여신·외상 정산 | 거래 데이터 축적 |

**왜 금융(Stage 5)이 큰가:** 우리는 각 매장이 *언제·뭘·얼마치 사는지*를 가장 정확히 아는 주체가 된다.
이 데이터는 곧 **신용평가 데이터**다. "오늘 받고 30일 후 결제(BNPL)" 같은 외상·여신을 깔면,
거래액 자체에 **금융 마진**이 얹힌다. 영세 카페일수록 현금흐름이 빡빡해 BNPL 수요가 크고,
이건 수수료보다 마진율이 훨씬 높은 레이어다. → **데이터가 결국 금융으로 수익화된다.**

## 9. 진입 전략 / 로드맵 (초안)

1. **Phase 0 — 가치 증명:** 엑셀 업로드 + 오픈 API(토스) 1종으로 MVP. **무인카페(비치헤드)** 소수에
   "예측발주(원두/우유/컵)" 정확도 검증. BOM은 메뉴 1회 등록으로 최소화. (수익: SaaS)
2. **Phase 1 — 일반 카페로 확장:** 무인 레퍼런스를 들고 **일반 개인·소형 카페**로 확대.
   닫힌 POS 1~2위 로컬 에이전트, 공급사 2~3곳 입점(원두 카테고리 락인).
3. **Phase 2 — 마켓플레이스:** 멀티벤더 최저가/재고/배송 라우팅. (수익: 중개수수료 + 광고)
4. **Phase 3 — 예측보충 + 금융:** 공급사 VMI/예측배송, 매입 데이터 기반 **BNPL/여신**. (수익: 금융)

## 10. 리스크

- 코케비즈가 자본·매장 수 선점 → **속도 경쟁**. "예측 자동발주"라는 차별점을 빠르게 못박아야.
- 예측이 핵심 가치인데 **콜드스타트**(초기 소진 데이터 부족 시 정확도 약함).
- 영세·이탈 잦은 고객군 → 객단가·리텐션 관리 필요.
- 닫힌 POS 로컬 에이전트의 유지보수·법적 리스크.
- 금융(BNPL) 레이어는 **연체·여신 리스크 + 규제**(여신업 라이선스) 동반 → 거래 데이터 충분히 쌓은 뒤.
