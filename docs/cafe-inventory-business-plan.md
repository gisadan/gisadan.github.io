# 카페·외식업 구매 운영체제 (Procurement OS) — 사업계획서 (v0.3)

> ## **"점주가 발주를 하는 게 아니라, 시스템이 발주한다."**
> ## **판매 데이터를 실제 구매로 바꾼다.**
>
> *Shopify가 온라인 쇼핑몰의 운영체제였다면, 우리는 오프라인 카페·외식업의 **구매 운영체제(Procurement OS)**가 된다.*
> *(규모를 동일시한다는 뜻이 아니라, 'OS'가 하는 역할 — 한 영역의 흐름 전체를 표준 인프라로 장악하는 것 — 을 가리킨다.)*
>
> 키오스크/POS 판매 데이터를 읽어, 점주가 *누르지 않아도* 원두·부자재가 떨어질 시점을 예측해
> 자동으로 채우는 서비스로 시작한다. 그러나 최종적으로 만드는 것은 *재고관리 앱*도 *발주앱*도 아니다 —
> **POS → 수요예측 → 발주 → 공급사 → 배송**으로 이어지는 카페·외식업 **구매 흐름 전체를 장악하는 인프라**다.

작성일: 2026-06-27 · 상태: 아이디어 검증 단계 (브레인스토밍 정리본)

## 1. 문제 (Problem) — Pain = 돈

카페는 원두·우유·시럽·컵을 **수기/전화/카톡으로** 발주한다. POS엔 판매량이 전부 디지털로 찍히는데
그게 재고·발주와 끊겨 있다. 그 결과 **돈이 새는** 두 방향:

| 새는 곳 | 메커니즘 | 추정 손실 |
|---|---|---|
| **품절 (재고 부족)** | 원두·우유 떨어지면 그 시간 매출 0. 인기 메뉴 못 팖 | 1회 발생 시 **하루 매출 ~30만원** 손실 |
| **과잉·폐기** | 불안해서 과발주 → 유통기한 폐기, 현금 묶임 | **월 15~20만원** 폐기 손실 |
| **수동 발주 노동** | 재고 세고 단가 비교하고 주문하는 시간 | **월 10시간+** (점주 기회비용) |

→ 투자자 언어로: 이건 "편함"이 아니라 **회수 가능한 돈**이다. (§9 Unit Economics에서 ROI로 정량화)

## 2. 왜 지금인가 (Why Now)

*"왜 5년 전엔 안 됐고, 지금은 되는가?"* — 네 흐름이 **이제야** 동시에 맞물렸다.

| 변화 | 5년 전 | 지금 |
|---|---|---|
| **POS API 개방** | 전부 폐쇄. 데이터 못 뺌 | 토스플레이스 등 **Open API 등장** — 균열 시작 |
| **키오스크 보급** | 일부 매장만 | 무인·소형 카페까지 **사실상 표준** → 판매 데이터 100% 디지털 |
| **무인카페 증가** | 미미 | **성장 축**으로 폭증 → 자동화가 *필수*인 수요 발생 |
| **수요예측 성숙** | 룰 기반, 부정확 | 모델 성숙 → **적은 데이터로도** 소진 예측이 실용화 |

→ 데이터를 뺄 수 있고(API) + 디지털이고(키오스크) + 절박하고(무인) + 예측이 정확해진 **딱 그 교차점**이 지금이다.

## 3. 왜 우리인가 (Why You) — *작성 필요*

VC는 Why Now·Why This만큼 **Why You**를 본다. *"왜 당신이 POS·예측·공급망 자동화를 만들 수 있는가?"*
아래는 채워야 할 칸 (해당되는 근거로):

- [ ] **도메인:** 카페/외식업 운영·창업 경험? 공급망·식자재 유통 경험?
- [ ] **기술:** POS 연동·데이터·예측모델·하드웨어(IoT) 개발 역량?
- [ ] **네트워크:** 공급사·POS 벤더·파일럿 매장에 닿을 수 있는 관계?
- [ ] **왜 이 문제에 집착하나:** 직접 겪은 페인 스토리 (가장 설득력 큼)

> 💡 Why You가 약하면, "이 팀이 POS 파편화와 공급사 온보딩이라는 *지저분한 실행*을 끝까지 해낼 수 있나"
> 라는 의심을 못 지운다. 한 줄이라도 구체적 근거를 박을 것.

## 4. 타겟 (Who) — 개인·소형 카페 전반 (무인은 초기 비치헤드)

- 한국 커피시장 규모 **19~21조 원**, 커피전문점 **10만 개+**. 영세·이탈 잦은 포화 시장이지만 모수 자체가 거대.
- **최종 타겟: 개인·소형 카페 전반** — 본사가 없어 최저가 발주가 자유롭고, 발주를 수기로 하는 곳이 대부분.
- **초기 진입(비치헤드)은 무인카페** — *처음 뚫고 들어갈 지점*: ① 키오스크 100%라 데이터 디지털,
  ② 사람이 없어 자동화가 *필수* → 가치가 가장 뾰족. 여기서 레퍼런스 쌓고 **일반 카페로 확장**.
- (장기) 소형 체인·로컬 프랜차이즈. 단 메가커피급 대형 프랜차이즈는 **본사 차액가맹금** 구조로 외부 발주를 막음 → 후순위/제휴.

## 5. 경쟁 (Competition) — 경쟁축은 '예측'이 아니라 '구매 흐름 전체'

| 플레이어 | 정체 | 핵심 |
|---|---|---|
| **코케비즈**(컨슈머브릿지) | 카페 특화 납품 플랫폼 | 2년 만에 가입매장 **2만**(전국 ~20%). 간편발주+월정산 자동화 |
| **마켓로스팅** | 커피 원·부자재 직거래 앱 | 9만 개인카페 대상 |
| **마켓보로**(식봄/마켓봄) | 범용 식자재 플랫폼+SaaS | 식봄 거래액 2,341억(2025), POS 자동 재고차감. CJ프레시웨이 403억 투자 |
| **푸드팡** | 외식업 새벽배송(직접물류) | 농산물 중심, 누적투자 218억 |

**차별화 — 단, '예측발주'만으론 부족하다.** 경쟁사는 "예측 버튼" 하나 붙이면 따라온다.
그래서 진짜 해자는 *기능*이 아니라 **포지션의 차이**다:

```
   기존: "발주 플랫폼"            우리: "구매 운영체제(OS)"
   = 더 편하게 사는 쇼핑몰        = POS→예측→발주→공급사→배송→정산 전 흐름을 깔고 표준이 됨
   점주가 결정 → 산다             시스템이 결정 → 점주를 의사결정에서 제거
```

> **핵심 한 줄:** 우리가 파는 건 발주 편의가 아니라 **"점주를 구매 의사결정에서 제거하는 것"**이다.
> 모든 자동화의 본질(사람 → 시스템)을, 외식업 구매에서 끝까지 밀어붙인다.
> 경쟁은 예측 정확도 싸움이 아니라 **구매 흐름을 누가 먼저 인프라로 장악하느냐**의 싸움이다.

## 6. 핵심 난제 & 해법 — POS/키오스크 연동

데이터 난이도는 결국 **"닫힌 POS" 하나로 수렴**한다. 두 겹의 어려움:

1. **파편화·폐쇄:** 오케이포스(26만 가맹점)·포스뱅크(1위)·나이스·KIS 등 벤더마다 자기 DB·자기 API,
   표준 없음, 데이터 소유권 이슈로 잘 안 열어줌. (단 토스플레이스 등 신형은 Open API — 균열 중)
2. **BOM 환산:** "라떼 100잔" → "원두 1kg+우유 30L" 변환에 매장별 레시피 매핑·노이즈. 기존 플레이어가
   회피한 지점. → **판매 잔수 자체를 얻는 건 쉬움.** 어려운 건 환산과 판단.

### 해법: "POS 연동은 전제조건이 아니라 보너스" — 데이터 입력 등급제

| 티어 | 데이터 유입 | 점주 노력 | 적용 대상 |
|---|---|---|---|
| **오픈 API** | 토스플레이스 등 자동 | 0 | 열린 POS 매장 (기본 탑재) |
| **로컬 에이전트** | POS PC에 프로그램 설치 → 로컬 DB 읽기/자동 전송 | 0 (설치 1회) | **닫힌 POS 1~2위만** 외과수술식 |
| **엑셀 업로드** | 상품별 판매 export 파일 주 1회 업로드 | 주 1회 클릭 | 나머지 닫힌 POS (폴백) |
| **IoT 실측** | 원두 호퍼 스마트저울·냉장고 센서로 직접 측정 | 0 | 무인카페 (POS 자체를 건너뜀) |

- **재고는 실시간이 필요 없다.** 원두는 주 1~2회 발주하는 느린 신호 → 주 단위로 충분.
- **로컬 에이전트 주의:** 벤더·버전별 리버스, 업데이트 시 파손, 약관 회색지대 → **1~2위 벤더에만.** 규모 커지면 정식 제휴로 졸업.
- **데이터 거버넌스:** 데이터 주인은 **업주**. "업주가 동의해 자기 이득에 쓰는 것" → 정당한 사용, 벤더 반발 약화.
  - 설계 B(엣지) ⭐: POS PC에서 계산 끝내고 **"원두 5kg 발주" 결론만** 전송 → *"우리는 매출 안 가져갑니다"*가 메시지.

## 7. 네트워크 효과 & 진입장벽 (왜 SaaS가 아니라 플랫폼인가)

큰 돈은 수수료·거래액에서 나오고, 그 거래액은 아래 **선순환(플라이휠)**이 돌수록 기하급수로 커진다.

```
        점주 증가
           │
           ▼
      구매 데이터 증가  ──▶  예측 정확도 ↑ (매장 1,000곳 > 100곳)
           │
           ▼
      공급사 입점 증가  ◀── "주문 받으려면 들어와야 함"
           │
           ▼
      가격 경쟁 / 빠른 배송  ──▶  점주 혜택 ↑
           │
           ▼
       점주 더 증가  ──▶  거래액 ↑  ──▶  수수료 ↑
           └──────────── (다시 위로) ────────────┘
```

### 데이터 네트워크 효과 = 따라올 수 없는 해자

> 매장이 100곳일 때보다 **1,000곳일 때 예측 정확도가 더 높아진다**(소진 패턴·계절성·메뉴별 수요가
> 누적되므로). 정확도가 높아질수록 점주는 더 의지하고, 거래액이 커지면 **공급사는 더 많은 주문을 받기
> 위해 입점**하며, 공급사가 많아질수록 점주는 **더 낮은 가격·빠른 배송**을 받는다. 이 선순환은 시간이
> 지날수록 누적 데이터·공급망 밀도가 쌓여 **신규 경쟁자가 따라오기 구조적으로 어려운 진입장벽**이 된다.

코케비즈가 매장 수에서 앞서도 — 그들은 *간편발주(쇼핑 데이터)*만 쌓고 우리는 *소진·예측 데이터*를 쌓는다.
데이터 종류가 다르고, 우리 데이터가 예측을 강화하는 쪽이라 **시간이 갈수록 격차가 벌어지는 자산**이다.

## 8. 수익모델 — 단계적 확장

단일 수수료가 아니라, 데이터·거래량이 쌓일수록 **수익원이 한 층씩 열리는** 구조.

| 단계 | 수익원 | 설명 | 전제 |
|---|---|---|---|
| **Stage 1** | **SaaS 구독** | 예측발주·재고관리 툴 월 구독 | 매장 확보 |
| **Stage 2** | **주문 중개수수료** | 공급사 거래액의 % (마켓보로형) | 마켓플레이스 형성 |
| **Stage 3** | **광고/입점** | 공급사 노출·프로모션·우선순위 | 공급사 경쟁 발생 |
| **Stage 4** | **공급사 ERP** | 공급사 측 주문·재고·정산 SaaS | 공급사 다수 락인 |
| **Stage 5** | **Working Capital / Supply Chain Finance** | 매입 데이터 기반 외상정산·운전자본 공급(예: 30일 후 결제) | 거래 데이터 축적 |

> Stage 5는 *내세우는 핵심이 아니라 결과*다. 우리는 각 매장이 *언제·뭘·얼마치 사는지*를 가장 정확히
> 아는 주체가 되고, 그 데이터는 곧 **공급망 신용 데이터**다. 영세 카페일수록 현금흐름이 빡빡해
> 운전자본(SCF) 수요가 크다 — 거래액에 금융 마진이 얹히는 건 데이터가 쌓인 *뒤에 자연히 따라오는*
> 레이어이지, 처음부터 파는 상품이 아니다.

## 9. Unit Economics (1페이지) — *카페 1곳, 그리고 1,000곳*

> 모든 수치는 공개 통계 기반 **보수적 가정**(가설). 실제는 파일럿으로 검증 필요.
> 근거: 카페 원가율 25~33%, 개인카페 월매출 400만(주거)~800만(오피스)~1,000만+(일반), 원두 1kg 2~2.5만, 객단가 4,550원.

### (A) 매장 1곳 — 우리가 버는 돈
| 항목 | 가정 | 값 |
|---|---|---|
| 매장 월매출 | 개인카페 현실값 | **1,000만원** |
| 원부자재 구매액 | 원가율 30% | 월 **300만원** |
| └ 플랫폼 통과 가능액 | 신선·베이커리 제외 ~70% | 월 **210만원 (GMV/매장)** |
| **수수료 매출** | 중개수수료 7% | 월 **약 14.7만원** |
| **SaaS 매출** | 구독 | 월 **39,000원** |
| **합계 ARPU** | 수수료+SaaS | 월 **약 18.6만원 / 매장** |

### (B) 매장 1곳 — 점주가 버는 돈 (왜 결제하나 = ROI)
| 점주 효익 | 가정 | 월 가치 |
|---|---|---|
| 품절 방지(매출 보전) | 월 1회 품절 손실 방지 | **+30만원** |
| 폐기/과잉재고 감소 | 유통기한 폐기 절감 | **+15만원** |
| 발주·재고 노동 절감 | 월 10h × 1만원 | **+10만원** |
| 최저가 비교 절감 | 구매액 210만 × 4% | **+8.4만원** |
| **효익 합계** | | **≈ 63만원/월** |
| 비용 (구독료) | | **−3.9만원/월** |
| **ROI** | 63 ÷ 3.9 | **≈ 16배** |

→ *"월 3.9만원 내고 60만원 넘게 번다"* — 결제 이유가 숫자로 선다.

### (C) 매장 1,000곳 확보 시
| 지표 | 계산 | 값 |
|---|---|---|
| **월 GMV** | 210만 × 1,000 | **21억원/월** |
| **연 GMV** | × 12 | **약 252억원** |
| 수수료 매출(7%) | 14.7만 × 1,000 | 월 1.47억 → **연 ≈ 17.6억** |
| SaaS 매출 | 3.9만 × 1,000 | 월 0.39억 → **연 ≈ 4.7억** |
| **합계 매출** | | 월 ≈ 1.86억 → **연 ≈ 22.3억** |

> 카페 10만 개 시장에서 **1,000곳은 1%**. 코케비즈가 이미 2만 곳(20%)을 모았다는 건 *모객이 된다*는 증명.
> 1% 점유로 연매출 ~22억, 시장 10%(1만 곳)면 단순 비례로 **연 ~220억 + GMV 2,500억** — 여기에 Stage 3~5가 얹힌다.

## 10. 진입 전략 / 로드맵

1. **Phase 0 — 가치 증명:** 엑셀 업로드 + 오픈 API(토스) 1종 MVP. **무인카페** 소수에 예측발주 정확도 검증. (수익: SaaS)
2. **Phase 1 — 일반 카페로 확장:** 무인 레퍼런스로 **개인·소형 카페** 확대. 닫힌 POS 1~2위 로컬 에이전트, 공급사 2~3곳 입점.
3. **Phase 2 — 마켓플레이스:** 멀티벤더 최저가/재고/배송 라우팅. (수익: 중개수수료+광고)
4. **Phase 3 — 예측보충 + 공급망금융:** 공급사 VMI/예측배송, 매입 데이터 기반 SCF. (수익: 금융)

## 11. 리스크

- 코케비즈가 자본·매장 수 선점 → **속도 경쟁**. "구매 OS" 포지션을 빠르게 못박아야.
- 예측이 핵심인데 **콜드스타트**(초기 데이터 부족).
- 영세·이탈 잦은 고객군 → 객단가·리텐션 관리.
- 닫힌 POS 로컬 에이전트의 유지보수·법적 리스크.
- 공급망금융(SCF)은 **연체·여신 리스크 + 규제**(여신업) 동반 → 거래 데이터 충분히 쌓은 뒤.
