# 시치미: B2C → B2B 보안 유틸리티 전환 분석 (v0.1)

> **전략 명제:** 시치미를 **B2C(개인 화면 위장)로 검증·유통**한 뒤, **B2B 화면보안(시각적 정보유출 방지) 유틸리티**로 성장시킨다.
>
> 결론 한 줄: **방향은 옳다. 단, B2C를 굴리는 핵심 기능('위장')이 B2B 구매자와 적대적이라,
> B2B는 '확장'이 아니라 같은 엔진 위에 올리는 '다른 제품'으로 설계해야 한다.**

작성일: 2026-06-27 · 상태: 전략 검토

---

## 1. 왜 이 전략이 옳은가

- **Bottom-up PLG 정석.** 개인이 먼저 쓰고(싸고 빠른 유통), 그 사용자가 회사에 끌고 들어가는 경로 —
  1Password·Notion·Zoom·Grammarly가 전부 개인→기업으로 천장을 뚫었다.
- **B2C는 B2B의 무료 유통 채널이 된다.** 개인 사용자 = 레퍼런스·입소문·"우리 회사도 깔자" 트리거.
- **시치미는 이미 B2C 출시·과금 중** → 콜드스타트가 약하다(엔진·브랜드가 이미 있음).
- 랜딩페이지가 이미 *"꼼수"가 아니라 "어깨너머 노출(shoulder surfing) 막는 보안 위생 도구"*로 언어를 틀어둠 → B2B 다리를 의식적으로 깔아둔 상태.

## 2. 시장 검증 — '화면보안'은 실재하는 보안 카테고리다

개인 위장 도구처럼 보여도, B2B에는 **"시각적 정보유출 방지(Visual Data Leak / Visual Hacking 방지)"**라는 분명한 시장이 있다.

- **위협이 실측됨:** Ponemon·3M 글로벌 실험 — 시각적 해킹 시도 **91%가 성공**, **68%는 끝까지 들키지 않음**, 절반은 15분 내 발생.
- **기존 보안이 못 막는 빈틈:** 기존 DLP·망분리·암호화는 *로그인 이후 화면에 떠 있는 정보*는 못 막는다 → **화면 인식 기반 실시간 보호**가 별도 카테고리로 필요.
- **원격근무로 수요 급증:** IT 보안담당자 64%가 "원격근무자 화면이 훔쳐보기로 샐까" 우려.
- **법적 드라이버:** 개인정보보호법 강화 → 개인정보 조회 데스크의 화면 노출은 컴플라이언스 이슈.

## 3. ⚠️ 핵심 함정 — '위장' 기능이 B2B 구매자와 충돌한다

이 사업만의 고유 리스크. 시치미의 B2C 킬러 기능은 **"위장(가짜 메모장/할일로 변신)"** = 뒤에 오는 사람한테서 내 화면을 *속여서* 숨기는 것.

| | B2C | B2B |
|---|---|---|
| **구매자** | 숨기고 싶은 **직원 본인** | 그 직원의 **회사 보안팀/IT** |
| **동기** | 상사한테서 카톡·주식 가림 | 직원이 정보 유출/딴짓 하는 걸 *막고* 싶음 |

→ **직원이 숨기려던 바로 그 대상에게 팔아야 한다.** "사장 몰래 카톡 가리기"가 소비자 후킹인 제품을
사장 보안팀에 파는 구조. FAQ 1번에 *"회사 몰래 쓰는 꼼수 아닌가요?"*를 스스로 달아야 했던 게 이 긴장의 증거.

## 4. 그래서 B2B는 '확장'이 아니라 '엔진 위의 다른 제품'

엔진(화면 인식 자동보호)은 재사용하되, **제품을 재정의**해야 한다.

| | 버릴 것 (B2C 전용) | 남길 것 (B2B 핵심) |
|---|---|---|
| 기능 | 가짜 화면으로 **속이는 위장** (메모장/할일 변신) | **시선 떼면 자동 블러 / 타인 접근·카메라 감지 / 화면공유 중 민감정보 자동 가림 / 자리비움 자동 잠금** |
| 프레임 | "상사 몰래" (적대적·꼼수) | "정보유출 방지·컴플라이언스" (정당·보안) |

> **핵심:** "위장(속임)"은 윤리적 회색지대라 B2B 문턱을 못 넘는다. **"자동 보호"만 떼어내면** 기업가치가 분명하고
> 깨끗하다. 이건 이미 가진 *"Cover Engine = 내부는 플랫폼"* 사고와 동일 — 엔진 1개 위에 B2C(위장)·B2B(보호) 두 제품.

## 5. B2B 타겟 세그먼트 & 지불의향

화면에 **개인정보(PII)를 띄워놓고 일하는 곳** = 화면보안 예산이 있는 곳:

| 세그먼트 | 왜 산다 | WTP |
|---|---|---|
| **콜센터·고객상담** | 고객 PII 상시 조회, 자리 이동 잦음, 다중 인원 | 높음 |
| **금융·보험 창구/심사** | 계좌·심사·승인 정보, 규제 강함 | 매우 높음 |
| **병원·공공기관** | 환자/민원인 정보, 법적 의무 | 높음 |
| **재택·원격근무 보안** | 집·카페 화면 노출, 통제 사각 | 중~높음 |

→ B2C 개인은 "있으면 편함(비타민)", B2B 이 세그먼트는 **"규제·사고방지(진통제+예산)"**.

## 6. 경쟁 — 한국에 이미 화면보안 incumbent가 있다 (중요)

B2B는 빈 땅이 아니다. **시치미 자동보호 엔진의 B2B판이 이미 팔리고 있음:**

| 플레이어 | 정체 |
|---|---|
| **FaceLocker (PNP시큐어)** | 카메라 촬영·**타인 접근·자리비움·다중 인물 노출** 감지로 로그인 후 화면유출 차단 — *시치미 자동보호와 거의 동일 기능을 B2B로* |
| **소만사·오피스키퍼·수산아이앤티·엑소스피어** | DLP·정보유출방지 종합 (출력물·망분리·화면) |

**시사점:** B2B에서 시치미는 *최초가 아니다.* "접근하면 가린다"는 기능 자체로는 차별화 안 됨.
가능한 차별점 → ① **B2C에서 키운 브랜드·유통 깔때기(bottom-up)**, ② **무겁고 비싼 엔터프라이즈 DLP가 안 건드리는 SMB·개인사업자·재택 개인**을 가볍고 싸게, ③ **앱별 커버 + 번호 전환 UX**의 사용성. 정면(대기업 금융)은 incumbent와 조달싸움 → 불리.

## 7. B2B 진입 전제조건 (현재 대부분 0)

B2B 보안은 B2C와 요구사항이 다르다. 아래 없이는 미팅조차 안 됨:

1. **코드 서명** — *최우선.* 지금 미서명이라 SmartScreen 경고 → B2C는 우회 가능하지만 **B2B는 즉시 탈락.**
2. **중앙 관리 콘솔** — 정책 배포(GPO/MDM), 사용자 관리, **감사 로그**.
3. **보안 인증** — ISO27001·개인정보, 공공이면 CC/조달 등록.
4. **B2B 영업 모션** — 쇼츠/SEO가 아니라 POC·보안검토·조달. 긴 사이클(또 다른 근육).

## 8. 재포지셔닝 로드맵

1. **Phase 0 — B2C 검증·현금흐름:** 지금 그대로. 무료(30회)→구독 깔때기·쇼츠로 *수요·유통 증명*. (이미 진행)
2. **Phase 1 — 보안으로 재정의:** "위장" 마케팅 비중↓, **"자동 보호·프라이버시"** 메시지↑. **코드 서명** 완료. 재택 개인/프리랜서에 "보안" 앵글로 판매 시작(B2B 워밍업).
3. **Phase 2 — SMB B2B:** 중앙 콘솔 MVP + 팀 라이선스(좌석 단위). 콜센터·소형 금융대리점·병의원 데스크 파일럿. incumbent가 안 가는 **가볍고 싼 티어**로 진입.
4. **Phase 3 — 엔터프라이즈/인증:** 인증 취득 후 금융·공공. (자본·시간 큼, 후순위)

## 9. 카페 OS와의 우선순위 결론

B2B 보안 경로가 진짜면 **시치미도 벤처 천장이 생긴다** → 둘 다 벤처급. 문제는 *동시에 못 한다.*

- **시치미 B2B 보안:** 이미 굴러가는 제품 위 확장, 콜드스타트 약함, 천장 "괜찮은 보안 SaaS"(수십~수백억). 리스크 ↓
- **카페 구매 OS:** 천장은 더 큼(인프라급)이나 실체 0 + 공급사·POS·자본이라는 더 무거운 미검증 리스크.

> **추천:** **시치미 B2B 보안에 먼저 집중**이 리스크-리턴상 영리. 카페 OS는 "언젠가 칠 큰 베팅"으로 두고,
> 시치미에서 번 돈·신뢰로 나중에 친다. **단 성패의 분기점 = "위장을 버리고 보안으로 재정의할 수 있느냐."**

## 10. 리스크

- **위장→보안 재정의 실패:** 위장이 좋아 B2C가 됐는데 그걸 못 버리면 B2B 문턱을 못 넘음. (1순위 리스크)
- **incumbent 경쟁:** FaceLocker 등이 이미 기능·레퍼런스 보유 → 정면 충돌 시 불리.
- **전제조건 비용:** 코드서명·콘솔·인증은 시간·돈. B2C 인디 속도와 상충.
- **영업 근육 전환:** 셀프서브 → 엔터프라이즈 세일즈는 완전히 다른 역량.
- **브랜드 이중성:** "상사 몰래 카톡" 이미지가 보안 브랜드 신뢰와 충돌할 수 있음 → 브랜드 분리 검토.
